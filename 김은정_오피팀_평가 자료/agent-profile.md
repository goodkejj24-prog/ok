# 법무사보수 자동계산기 (부동산 시세 임장리스트)

## 1. 해결하려는 문제

- **Pain Point**: 부동산 매수 검토 시 취득세, 중개수수료, 법무사보수 등 부대비용을 매번 수동 계산해야 하며, 토지거래허가구역 여부에 따라 실투자금 산출 방식이 달라져 혼란이 발생함
- **As-Is**: 엑셀이나 계산기로 매물별 취득세(1.1%), 중개수수료(0.4%)를 하나씩 계산하고, 갭투자 가능 여부를 별도로 확인한 뒤 실투자금을 수기로 산출 → 시간 소모 크고 실수 가능성 높음
- **To-Be**: 매매가/전세가/토허제 여부만 입력하면 취득세·중개수수료·실투자금이 자동 산출되고, 갭투자 가능 여부에 따라 투자유형별 필요 자본금이 즉시 표시됨. 4개 지역 40+개 매물에 대해 일괄 자동 계산 및 비교 가능

## 2. 설계 구조

### 핵심 기능 목록
1. **취득세 자동계산**: 매매가 × 1.1% (취득세율 상수 기반)
2. **중개수수료 자동계산**: 매매가 × 0.4% (중개수수료율 상수 기반)
3. **토지거래허가구역 판정**: 아파트 소재지 법정동 기준 토허제 여부 자동 매칭
4. **투자유형 자동분류**: 토허제 → "실거주(토허제지역)" / 비토허제 → "갭투자 가능"
5. **실투자금 산출**: 갭투자 가능 시 갭+취득세+중개비, 토허제 시 매매가+취득세+중개비
6. **2년 투자 적합도 점수**: 입지환경·선호도·교통 호재 기반 0~100 점수 산출
7. **대시보드 시각화**: Next.js 웹 UI로 지역별 매물 카드에 자동계산 결과 표시

### 워크플로우 흐름
1. 아파트 마스터 목록 구축 (지역·면적·세대수 필터링)
2. 매매가/전세가 데이터 수집 (네이버 부동산 + 국토교통부 API)
3. 토지거래허가구역 여부 확인
4. 갭(매매가-전세가), 전세가율 계산
5. **취득세·중개수수료·실투자금 자동계산** ← 핵심 자동계산 로직
6. 투자유형 판정 및 2년 투자 적합도 산출
7. 대시보드에 결과 렌더링 (정렬: 실투자금순, 종합랭킹순 등)

### 사용한 주요 도구/스킬
- **Claude Code**: 전체 프로젝트 구현 오케스트레이션 (멀티 에이전트 구조)
- **Next.js 16 + React 19**: 프론트엔드 대시보드 프레임워크
- **TypeScript strict**: 타입 안전한 계산 로직 구현
- **shadcn/ui**: Badge, Card, Separator 등 UI 컴포넌트
- **Tailwind CSS 4**: 반응형 스타일링
- **법무사보수표 PDF (2024.9.12 시행)**: 공식 보수 기준 참조 자료

## 3. 기술적 특이사항

### 구현 시 어려웠던 점과 해결 방법
1. **투자유형별 분기 로직**: 토허제 지역은 갭투자 불가(매매가 전액 필요), 비토허제 지역은 갭만 필요 → `isLandPermitZone` boolean 플래그로 분기하여 `realInvestment` 산출 공식을 달리 적용
2. **데이터 일관성**: 4개 지역 × 다수 매물에 대해 동일한 계산 로직 보장 필요 → `createApartment()` 팩토리 함수에 계산 로직을 집중시켜 모든 mock-data 파일에서 동일 공식 적용
3. **가격 표시 포맷**: 억/만 단위 혼합 표기(예: "2억 3,000만") → `formatPrice()` 유틸리티로 자동 변환
4. **법무사보수표 연동**: 공식 PDF 기준 보수율을 상수(`ACQUISITION_TAX_RATE`, `BROKERAGE_FEE_RATE`)로 정의하여 변경 시 한 곳만 수정

### 핵심 지시사항 요약 (설계서 기반)
- 멀티 에이전트 구조: designer → developer → tester 순서 실행
- 크롤링 시 rate-limit 준수 (요청 간 2초 딜레이)
- 갭투자 분석: 토허제 여부 + 실투자금 산출을 Step 6에서 자동 수행
- 실투자금 공식: 갭투자=갭+취득세+중개비, 토허제=매매가+취득세+중개비
- shadcn 컴포넌트 사용, TypeScript strict 모드
